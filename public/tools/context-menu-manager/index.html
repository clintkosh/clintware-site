Admin PowerShell security boundary

NORMAL EXPLORER → fixed Clintware request helper → validated FileSystem working-directory path only → pre-authorized Task Scheduler task → protected broker under %ProgramFiles%\Clintware\ContextTools → fixed pwsh.exe / Windows PowerShell path → -NoProfile -NoExit TASK ACL normal user token: READ + EXECUTE SYSTEM / elevated Administrators: FULL CONTROL

The first installation still requires administrator consent. The broker then persists across reboot. UAC remains enabled globally and ordinary applications continue to elevate normally. The task is deliberately ACL-hardened because a default creator-writable highest-privilege task would be too broad.

Rollback and repair

BASELINE + LEDGER

Before the first change to a compatible third-party verb, Clintware records its enabled state. Each Apply creates another timestamped change record. Undo Last Apply reverses the most recent delta; Restore Baseline returns previously changed compatible verbs to first-seen state.

REPAIR

A degraded Clintware module can be repaired from the manager. Repair is one of the few operations that may ask for UAC again because rebuilding the protected Program Files broker or scheduled task crosses the administrator boundary.

What v0.3.0 does not claim

This beta does not control every Windows 11 context-menu implementation. It safely toggles ordinary compatible HKCU registry verbs and treats machine-level or handler-backed integrations as read-only. Broader Windows runtime validation and signed executable packaging remain next steps.
