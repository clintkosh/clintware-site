ShoulderSoldier

Provider-independent protection before a user acts on risky email content. The product track explores a local or client-side layer that can inspect links, attachments, message structure, and interaction risk without making one downstream mail-security vendor the product itself.

Why this track exists

Gap
Many controls become relevant after the message has already reached the user.The product question is whether a lightweight client-side layer can create useful protection at the point of interaction, especially across providers and account types.
Independence
The protection model should not depend on one mail gateway being installed.Provider independence is part of the thesis. It also creates hard questions around compatibility, privacy, browser/client permissions, and false positives.
Human factor
The system should reduce dangerous exposure without training users to ignore warnings.Blocking everything or adding constant friction is not a security product. The intervention needs to be timely, explainable, and proportionate to risk.

Current boundary

This is an active product track, not a claimed production security platform. The next evidence needed is a narrow working prototype, measurable detection/interaction value, privacy-safe implementation boundaries, and proof that users will tolerate the intervention. Quillgeist and LandThePlane remain the Fall 2026 YC application candidates.
