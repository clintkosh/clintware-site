Quillgeist

A local execution layer for AI work that should not require a cloud model for every step.

Most AI workflows mix two different jobs: deciding what should happen and carrying out routine computer work. That creates repeated prompting, unnecessary context transfer, more cloud usage, and weak evidence that the work was actually finished. Quillgeist separates those jobs. Model reasoning is used where judgment is needed. Eligible deterministic work can stay on the user's machine. The result comes back with checks and evidence.

Status: working public alpha. Quillgeist is being prepared as Clintware's primary Fall 2026 Y Combinator application candidate. It is not presented as accepted by, affiliated with, or endorsed by Y Combinator.

Overview

The thesis in plain terms.

Quillgeist is an execution and control layer between the person, the model, and the local computer.

Problem
AI users repeatedly resend context and ask models to supervise work their own computer can perform directly.Files, shell commands, tests, Git operations, schedules, and other deterministic steps often do not need a large model in the loop for every action.
Product
Separate reasoning from execution.Quillgeist receives the requested outcome, applies local policy, executes eligible work on a paired machine, and sends compact results back for the parts that still require model judgment.
Control
The local machine remains an explicit execution boundary.Capabilities can be allowed, require confirmation, or be blocked. Sensitive-data checks run before eligible execution and routing.
Verification
Completion should be inspectable.Tests, changed files, command results, snapshots, rollback state, and definition-of-done evidence are returned instead of a generic claim that the task succeeded.
What exists now

This is the current alpha, not the roadmap.

The page deliberately separates shipped capability from what still needs to be proven or built.

LOCAL NODEWindows, macOS, and Linux builds.
EXECUTIONFilesystem, processes, Python, PowerShell, Node.js, Git, tests, schedules, snapshots, rollback.
CLOUD CONTROLPair a machine, dispatch work, inspect execution history and results.
POLICYLocal allow / ask / never capability controls and sensitive-data checks.
Result packaging
Large execution output can be compacted before it is returned upstream.The aim is to send useful evidence and exceptions rather than every local intermediate step.
Telemetry
Operational telemetry is account-scoped without intentionally storing prompt or file contents.This is for execution reliability and product learning, not a reason to move private local work into the cloud.
Not finished
Adaptive instruction learning is still under active development.The long-term product should learn from accepted edits, rejected edits, preferences, corrections, and task outcomes so users repeat themselves less. That should not be described as shipped until it is demonstrated reliably.
Execution path

What happens when a user gives Quillgeist work.

01 · Intent
Receive the requested outcome and constraints.Make the definition of done explicit enough that completion can be checked.
02 · Route
Decide what is deterministic/local and what still needs model reasoning.Do not pay a model to supervise every command simply because the workflow started in an AI interface.
03 · Execute
Run approved local work under the machine's capability policy.Use local tools, tests, snapshots, and rollback where appropriate.
04 · Return
Send back the result, exceptions, and proof.The upstream model or user should receive enough evidence to make the next decision without consuming the full local execution trace.
YC case

What has to be true for Quillgeist to deserve a Fall 2026 YC application.

The technical alpha is not the company by itself. The company case depends on repeated behavior and measurable reduction of friction.

Repeat use
Users repeatedly delegate meaningful work, not just run a demo once.Retention and tasks per active user matter more than raw installs.
Local leverage
A meaningful share of execution can stay local without harming completion quality.That should reduce unnecessary cloud calls, transferred context, latency, or cost in a way users notice.
Trust
Users are willing to give Quillgeist controlled access to real work because the permission and evidence model is understandable.A product that can execute but is not trusted is not useful.
Learning
The adaptive layer actually reduces repeated instruction over time.This is the larger thesis and the most important unproven part.
