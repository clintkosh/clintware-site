The product thesis

The useful layer is between human intent and model execution.

A user should not have to repeatedly rewrite prompts, restate preferences, or spend model context on deterministic machine work. Quillgeist makes that translation and routing layer explicit.

The local execution backbone is already working. Adaptive intent compilation and interaction learning are the product layer now being built on top of it.

The loop

TYPE → UNDERSTAND → IMPROVE → EXECUTE → LEARN

The value compounds when each interaction leaves useful signal for the next one.

1 · TypeCommunicate normally instead of learning prompt syntax.
2 · UnderstandIdentify intent, constraints, context, and completion criteria.
3 · ImproveCompile a clearer instruction and explicit definition of done.
4 · ExecuteUse local execution, tools, or a model based on what the task requires.
5 · LearnUse edits, replies, accepted changes, recurring patterns, and outcomes as feedback.

Working in the public alpha

  • Cross-platform local Node for Windows, macOS, and Linux.
  • Execution Packs with permissions, constraints, steps, and definition-of-done checks.
  • Local allow / ask / never capability policy.
  • Filesystem, process, Python, PowerShell, Node.js, Git, tests, checks, scheduling, and rollback support.
  • Contextor output compaction and Result Packs with verified evidence.
  • Cloud pairing and account-scoped execution history.

Quillgeist product layer

  • Real-time intent compilation while the user writes and works.
  • Preference and correction memory from accepted, rejected, and edited suggestions.
  • Workflow recognition and reusable instruction patterns.
  • Model/tool routing informed by task type, policy, cost, and local capability.
  • Evaluation against explicit definition-of-done and successful outcomes.
  • Portable learning outside model weights rather than unsupported autonomous retraining claims.

Why the learning loop matters

The same correction should not be paid for twice.

If you consistently rewrite a tone, reject a routing choice, add the same constraint, or prefer one workflow, that is useful product signal. Quillgeist is designed to preserve that signal so the next compiled instruction starts closer to how you actually work.
