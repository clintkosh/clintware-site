Quillgeist

Adaptive intent compiler for AI.

The user should not have to become a prompt engineer every time they want something done. Quillgeist is being built to take normal intent, resolve the missing context and constraints, improve the instruction for the model or tool being used, execute eligible work on the user's own computer, verify the result, and learn from corrections so less has to be restated next time.

What is real today: a working cross-platform local-execution alpha with cloud pairing/control, capability policy, tests, Git/process/file operations, snapshots, rollback, and inspectable result evidence. Adaptive learning is the larger thesis and is still under active development.

The product loop

The implementation can change. This is the product direction that should remain recognizable.

01TYPEThe user says what they want in normal language rather than constructing a perfect machine instruction.
02UNDERSTANDResolve the actual goal, relevant context, constraints, tools, permissions, and definition of done. Ask only for information that is genuinely missing.
03IMPROVEPrepare the instruction and context the target model or execution layer needs. The point is not prettier prompting; it is reducing ambiguity before execution.
04EXECUTERoute eligible deterministic work to the paired local machine while using model reasoning where judgment is actually required. Return checks and evidence against the definition of done.
05LEARNUse accepted edits, rejected edits, corrections, preferences, and outcomes to reduce repeated instruction over time. This is the adaptive layer that still has to be proven in sustained use.

Why this exists

Repeated context
Users keep re-explaining the same preferences, environment, constraints, and standards.Chat history and giant system prompts are weak substitutes for a deliberate layer that knows what is stable, what changed, and what matters to this task.
Execution overhead
Cloud models are often asked to supervise deterministic steps they do not need to reason about.Files, shell commands, tests, Git operations, schedules, and other routine execution can often happen locally, with only exceptions or ambiguous decisions sent back for model reasoning.
Weak completion
“Done” is too often a claim instead of evidence.Quillgeist treats tests, changed files, command output, snapshots, rollback state, and explicit checks as part of the returned result.

Current alpha proof

These are current capabilities, not future promises.

LOCAL NODEWindows, macOS, and Linux builds.
EXECUTIONFilesystem, process, Python, PowerShell, Node.js, Git, tests, schedules, snapshots, rollback.
CLOUD CONTROLPair a machine, dispatch work, inspect execution history and results.
POLICYAllow / ask / never capability controls plus sensitive-data checks before eligible execution/routing.
Result packaging
Compact the useful evidence instead of returning every local intermediate step.The upstream model or user should receive enough to make the next decision without paying to re-read the entire execution trace.
Telemetry boundary
Operational telemetry is account-scoped without intentionally storing prompt or file contents.The cloud should coordinate and measure reliability without becoming an excuse to copy private local work upstream.
Not claimed as finished: adaptive instruction learning, durable preference learning, broad automatic routing, and proof that Quillgeist materially lowers cost/friction over long-term real workflows. Those are the product thesis to validate, not features to backfill into marketing copy.

What would make the Fall 2026 YC case stronger

Repeat use
People repeatedly delegate meaningful work, not just run the alpha once.Tasks per active user and return behavior matter more than downloads.
Local leverage
A meaningful share of work stays local with no loss in outcome quality.That should show up as lower context transfer, fewer unnecessary model calls, lower latency/cost, or a workflow users can run that was previously too cumbersome.
Trust
Users allow controlled execution because permissions and result evidence are understandable.Execution capability without trust is not a useful product.
Learning
Corrections measurably reduce future repetition.This is the key step from useful executor to adaptive intent compiler.
