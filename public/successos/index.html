Carry your AI computer with you.

Clintware SuccessOS is a portable, local-first operating environment designed to boot from removable media, run without an internet connection, understand natural-language intent, and execute system changes only through explicit scoped permission.

Architecture defined

Linux underneath. Governed AI above it.

SuccessOS does not ask a language model to be a kernel. A standard Linux kernel and userland handle hardware, filesystems, networking, process isolation, and security. The AI layer interprets intent and proposes actions. A deterministic capability broker decides what may actually run.

success> connect this laptop to my office Wi-Fi

Plan: enable wireless radio → scan known networks → connect to saved SSID
Scope: NetworkManager / Wi-Fi only
Risk: reversible local change

[1] Allow once   [2] Allow for this session   [3] Always allow this scoped action   [4] Deny

Permission is a product feature.

Allow onceOne exact operation against one exact resource. Permission expires immediately after the result is verified.
SessionPermit a narrowly defined capability until logout, reboot, or an explicit revoke.
Always allowCreate a durable local rule only for the shown tool, resource boundary, identity, and risk class. Broad wildcard grants are rejected.
DenyReject the request. Optional deny rules can persist so repeated prompts stop appearing.

The model never grants itself authority. Privileged operations are mediated outside the model process, logged, reversible where possible, and re-prompted whenever scope expands.

Built to boot on ordinary hardware.

Broad offline driver set

Ship common storage, display, Ethernet, Wi-Fi, Bluetooth, USB, audio, touchpad, camera, and firmware support in the image rather than making first boot depend on a network connection.

Deterministic driver discovery

Probe PCI, USB, ACPI, and modalias identifiers; match installed kernel modules and firmware; then show exactly what is missing before any download is attempted.

Signed online completion

When online, fetch missing packages only from configured signed repositories, verify package metadata, install the minimum matching driver or firmware, and record the change.

Start portable. Grow only when needed.

Live mode

Boot and work without writing to the host disk. Useful for testing, recovery, privacy, and unfamiliar hardware.

Persistent mode

Keep encrypted user files, models, preferences, approvals, and local memory on removable storage.

Full workstation

Promote the same environment into a normal disk installation when the user wants a permanent Linux workstation. The agent produces a reviewed migration plan before storage changes.

A Windows path is treated as a migration decision, not an in-place mutation of Linux into Windows. SuccessOS can inventory the machine, preserve user data, prepare installation media and drivers, and generate a verified migration plan before the user explicitly authorizes replacement of the host OS.

Offline-first intelligence.

The local inference path is designed around BitNet-class CPU models for reasoning and compact embedding models for local semantic search. Internet access is optional augmentation, not a boot dependency. Local documentation, hardware knowledge, recovery procedures, file search, and routine system actions remain available offline.

LOCAL MODEL → LOCAL MEMORY → LOCAL TOOLS → OPTIONAL REMOTE CAPABILITIES

One control plane, two access paths.

SuccessOS uses the Clintware MCP boundary for remote account capabilities and shared state. Native SuccessOS components can call that MCP endpoint directly using delegated authorization. A separate Clintware plugin packages repeatable skills, onboarding, and client-specific presentation for ChatGPT and Codex without becoming a second authority layer.

SuccessOS native

Direct MCP client → scoped OAuth token → capability gateway → verified result.

ChatGPT / Codex

Clintware plugin → reusable skills + MCP connection → same capability and identity boundaries.

Local-only actions

Stay on-device through the SuccessOS capability broker. Remote services never receive local authority they do not need.
