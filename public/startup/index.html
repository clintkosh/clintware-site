STARTUP REVIEW · YC PRIORITY

Quillgeist reduces repeated instruction work between people, AI models, and local tools.

People repeatedly restate goals, preferences, constraints, tool details, and definitions of done. They also send work to external models that could be executed locally. Quillgeist is being built as an adaptive execution layer between user intent and the system doing the work.

Open working alphaTechnical product detail
Problem

AI users pay a repetition tax.

They rewrite prompts, re-explain preferences, restate execution constraints, and repeatedly move context between models and local tools.

Repeated context

The same correction appears again.

Accepted edits, rejected edits, preferences, and prior outcomes are often lost between sessions and tools.

Execution mismatch

Reasoning and routine execution are mixed together.

Some work needs a capable model. Some work is deterministic and can run locally with clear permissions and checks.

Verification gap

“Done” is often ambiguous.

Workflows need an explicit definition of done and evidence of what actually ran or changed.

Product

An intent and execution layer, not another chat window.

Improve
Turn normal-language intent into a clearer instruction.Goal, constraints, tools, context, and definition of done are made explicit for the model or tool being used.
Route
Separate local execution from external reasoning.Eligible deterministic work can run locally while the parts that need model reasoning are routed outward.
Learn
Use corrections and outcomes to reduce repetition.The adaptive layer is being developed to learn from accepted edits, rejected edits, preferences, and task outcomes.
Verify
Return evidence against the definition of done.Execution should produce inspectable results rather than a vague claim of completion.
Working now

Public alpha

  • Local execution on Windows, macOS, and Linux.
  • Permission-aware execution packs.
  • Filesystem, process, Python, PowerShell, Node.js, Git, tests, scheduling, and rollback support.
  • Compact result packages showing what ran and changed.
In active development

Adaptive layer

  • Real-time instruction improvement.
  • Memory from edits, preferences, and outcomes.
  • Reusable patterns for repeated workflows.
  • Routing by task type, capability, policy, and model need.
  • Evaluation against explicit completion criteria.
State boundary: roadmap functionality is intentionally separated from working alpha functionality.
