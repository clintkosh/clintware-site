The boundary that prevents report drift

difference_window = (latest_sent_report_at, current_at]

A draft does not move the clock. Neither does a preview, local export, or unsent revision. The next report starts at the previous report’s confirmed send time, whether the interval is six hours or three weeks.

What v1.4 adds

Evidence stateSource + time + confidence + verification

Material status claims can retain provenance and current state instead of collapsing direct evidence, inference, and old summaries into one undifferentiated narrative.

AccuracyStored-artifact readback

A successful API write or local render is not treated as proof that the saved result is correct. Consequential writes are re-read when the provider exposes stored state.

RenderingMobile-dark structural hardening

Email output uses structural dark backgrounds, inline color locks, explicit text colors, and responsive fallbacks rather than relying on media queries or a desktop preview alone.

The operating loop

  • Find the latest actually sent report.
  • Audit current recruiting evidence and application receipts.
  • Reconcile active, paused, waiting, stale-risk, closed, and unverified state.
  • Keep interval deltas separate from cumulative totals.
  • Build an evidence-state ledger for material claims.
  • Refresh market data and clearly label anecdotal signals.
  • Render the report without dropping prior approved improvements.
  • Re-read the saved artifact and repeat verification after any update.

What it refuses to fake

ASTRO does not turn email receipts into fake unique applications, networking intros into employer interviews, stale summaries into current state, compensation estimates into verified pay, anecdotal community posts into population statistics, or a local HTML preview into proof that Gmail stored the banner and dark-mode structure correctly.

Email acceptance is part of accuracy

When Gmail is the output system, the skill requires a real inline MIME banner rather than an ordinary attachment masquerading behind a local CID. After every create or update, the stored draft must be re-read for the generated CID and inline MIME state. Critical dark surfaces also retain explicit HTML bgcolor, inline background colors, same-color gradient locks, and explicit text colors.

Static mobile-hardening checks ≠ verified mobile-client rendering. If an actual target-client preview was not inspected, the workflow says so.
