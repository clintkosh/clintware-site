# NMA Customer Solutions Operating System — Presentation Narrative

Live demo: https://nma.clintware.com

## 1. Purpose

Run the strategic post-sales motion as one customer operating system instead of separating technical discovery, delivery, adoption, risk, value, executive communication, and expansion into disconnected records.

## 2. Operating loop

`ALIGN → DISCOVER → PRIORITIZE → DEPLOY → ADOPT → PROVE → EXPAND → SIGNAL`

Each step maps to an explicit Customer Solutions responsibility and a corresponding working surface in the application.

## 3. AI estate and security discovery

The synthetic golden account includes GenAI applications, LLM/RAG workloads, endpoint and homegrown agents, AI development pipelines, MCP servers, tools, identities, data paths, cloud environments, owners, and business objectives.

The goal is to make the environment legible enough to drive a security program rather than treating inventory as the end state.

## 4. Governance to runtime

The workflow keeps four concepts distinct:

- Discover: what exists, where, who owns it, and what it can reach.
- Govern: approved/review/blocked state, permissions, identities, owners, and decision rights.
- Test: pre-production security evidence and closure/risk-acceptance criteria.
- Protect: runtime policy, high-risk action coverage, event routing, and response ownership.

## 5. Measurable customer value

Outcome cards include baseline, target, metric definition, source, calculation, owner, cadence, current value, and approval state. This keeps activity and targets from being presented as realized customer value without evidence.

Synthetic examples include AI asset inventory coverage, priority MCP governance coverage, critical risk ownership, high-risk runtime coverage, and critical pre-production finding closure.

## 6. Retention, expansion, and cross-functional execution

Expansion is treated as a consequence of customer value and operational readiness. The workspace connects additional workloads/teams/business units to security readiness, control ownership, technical dependencies, executive decisions, and Sales strategy.

Product, Research, Engineering, Security, Support, and customer operationalization signals remain attached to the same account state.

## 7. CISO / GRC workflow

The executive review condenses technical state into decisions: current coverage, material risk, open dependencies, evidence sufficiency, owners, next actions, and where AI adoption can safely accelerate.

The application includes a generated CISO executive-brief PDF and a dedicated executive-review/prep surface.
