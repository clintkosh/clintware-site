Self-host Quillgeist Cloud

Hosted boundary: the Clintware distribution domain does not provide public account bootstrap, device pairing, remote execution, telemetry ingestion, schedules, REST execution, or MCP execution. Those routes return HTTP 410. Public Quillgeist nodes start local-only.

Local-only is the default

Install Quillgeist and use its local operating-context and execution features without configuring a cloud. No Quillgeist telemetry is sent by default.

Optional cloud routing

If you want device pairing, remote routing, schedules, or your own MCP/API surface, deploy the open Quillgeist Cloud worker under a domain and infrastructure you control. Then pair the node explicitly:

quillgeist pair --cloud https://quillgeist.example.com
quillgeist daemon

The node rejects Clintware-owned hostnames as pairing targets in public builds. Its device credential is generated locally for that installation; it is not a Clintware server credential.

Self-hosted API/MCP source

The repository includes the Quillgeist Cloud worker and MCP/API implementation for deployment to your own Cloudflare account/domain. Configure your own Worker route, Durable Objects, and secrets. Do not reuse Clintware credentials or endpoints.

Security rules

  • Local policy remains authoritative.
  • Keep provider secrets in your own deployment.
  • Use a domain you control.
  • Enable telemetry only if you choose to send it to your own configured instance.
  • Do not expose an unrestricted local shell through cloud routing.
