Quillgeist Privacy

Last updated: September 24, 2026
Public build: Quillgeist starts local-only, has Quillgeist telemetry disabled, contains no Clintware control-plane credential, and does not pair to Clintware infrastructure.

1. Download and local use

The public application stores its configuration and operating data locally. Cloud functionality is optional. Without an explicitly configured self-hosted cloud URL, the Quillgeist daemon does not start a Quillgeist cloud connection and telemetry is not sent.

2. Clintware-hosted distribution site

This domain distributes software and documentation. Public account bootstrap, device pairing, device WebSockets, remote jobs, schedules, telemetry ingestion, REST execution, and MCP execution are retired on the Clintware-hosted domain.

3. Self-hosted deployments

If you deploy Quillgeist Cloud yourself, that deployment is operated by you. Its logs, credentials, retention, and data processing depend on your configuration and infrastructure providers. Public Quillgeist nodes require you to configure that self-hosted URL explicitly.

4. Local telemetry setting

Quillgeist telemetry is off by default. If you explicitly enable telemetry after configuring your own cloud, operational metadata can be sent to that instance according to your settings. Prompt or file content should not be treated as telemetry.

5. Clintware website infrastructure

Ordinary web hosting and security providers may process normal request metadata when you visit the distribution website, such as IP address, timestamps, and HTTP headers. This is separate from the Quillgeist application runtime.

6. Contact

For questions about the Clintware distribution site, use clintware.com. For a self-hosted deployment, the operator of that deployment controls its data.
