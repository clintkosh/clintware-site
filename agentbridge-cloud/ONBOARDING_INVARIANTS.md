# Quillgeist onboarding invariants

This file is a regression lock for the public Quillgeist first-run experience.

## Permanent first-run rule

Quillgeist is a local-first product. A new visitor must never land on a page whose primary or only path is a control-key prompt.

The public first-run path must remain:

1. **Download Quillgeist** for the visitor's machine. The landing page must expose direct builds for Windows x64, macOS Apple Silicon, and Linux x64.
2. **Install/run the local executable** and initialize it locally.
3. **Continue to Quillgeist Cloud** to create/open the new Cloud account surface.
4. **Pair the local Node** using the short pairing code generated by the downloaded executable.
5. **Run the daemon and use Quillgeist.**

## Control-key rule

The control key is a returning-user/account-recovery mechanism. It must remain available, but it must never replace or outrank software download as the new-user call to action.

Allowed label pattern: `Existing user · use control key`.

Disallowed regression: a landing page led by `Open Quillgeist Cloud` / `Use existing control key` with no prominent software download choices.

## Release assets expected on the landing page

- `Quillgeist-Windows-x64.exe`
- `Quillgeist-macOS-arm64`
- `Quillgeist-Linux-x64`

The Quillgeist deployment workflow must fail validation if these download choices or the returning-user distinction disappear.
